## 3d. The import fence, both directions — and the second direction is not an import

**The instruction said to assume the other direction has its own hole. It has,
and it is not a hole in an import fence, because the crossing is not an
import.**

### What was already covered

| Direction | Instrument | State |
|---|---|---|
| Discovery layer → prices, outcomes, gates | `assert_import_fence` | in force |
| Item-pipeline modules → discovery layer | `assert_reverse_import_fence` | in force, returning **`NOT_APPLICABLE`**, because no such module exists yet, *and that is deliberately not `CLEAN`* |
| Filing corpus → discovery layer | `Corpus.__post_init__`, `corpusio.corpus_documents`, and the import-closure test | in force, three locks |

### The hole. **The two pipelines share a LEDGER.**

`CLAUDE.md` forbids agent-origin material entering the §3.5 item pipeline,
because it would re-base §7.1's headline on an agent-selected population.
**Both fences above check module imports.** *The discovery layer and the item
pipeline share a SQLite ledger, so the crossing is a `SELECT`, and a `SELECT` is
not an import.*

**Found by looking:** `queue_from_ledger` read

```sql
SELECT directive_id, event_class, delta_min, registered_sign, registered_at
FROM directive
```

***and did not select `origin`.*** **Every consumer built on it received a
directive list with the marker already stripped**, and the prohibition is
unenforceable at the point where the information is gone. *It could not have
refused agent material if it had wanted to.*

**This is the same shape as the underscore-directory hole the previous batch
found: the rule was right, and a read path walked round it.**

### The fence, written to fail first

`test_no_ledger_read_path_hands_out_a_directive_without_its_origin` failed with
`AttributeError: 'Draft' object has no attribute 'origin'` before the repair.

**The repair, in three parts:**

1. **`origin` travels with every directive read out of the ledger.** The
   `SELECT` carries it and `Draft` holds it.
2. **`Draft.is_discovery_origin` names the test once**, so consumers do not each
   invent their own and drift. ***`unrecorded` counts as discovery-origin***: a
   directive whose origin the ledger cannot state must not be admitted on the
   strength of a blank.
3. **The run report prints `origin` in the queue table**, so the marker is
   visible and not merely carried.

**The check that keeps it honest.** The queue's ranking-key test pinned the
header literal, so the new column had to be declared; the test now additionally
asserts that **no cell after the first is numeric**, which is the property it
was really protecting. *A provenance marker is admissible in that table; a
second number is not, because a reader given one ranks by it.*

### What this does NOT establish

**No agent-origin material can be shown not to reach the item pipeline, because
there is no item pipeline.** What is now true is that **the marker survives
every read path the ledger has**, so the pipeline that is eventually built can
refuse. *The fence is in place before the thing it fences, which is the order
this project has now twice wished it had used.*
