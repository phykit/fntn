# Replay of the run of record against the repaired intake path

**28 August 2026.** ***NON-EVIDENTIARY. Nothing in this file is a measurement, a
sweep, or an observation, and no row of it may be counted as one.*** It is the
27 August run of record's own agent emissions driven through the intake path
three times, so that what the repairs change is visible as a code distribution
rather than asserted in prose.

## What the fixture is, and what it can and cannot show

`docs/replay/run_of_record_agent_emissions.json` carries **the six proposals the
agent arm actually emitted on 27 August**, transcribed verbatim from
`docs/CANDIDATE_MECHANISMS.md`'s table *WHAT THE AGENT ARM ACTUALLY EMITTED*,
across the two calls that produced them. It is a **recording of what the clerk
returned under the pre-repair prompt.**

***That bounds what a replay can demonstrate, and the bound is not a detail.***

| Repair | Demonstrable here? |
|---|---|
| **B6**, `unclassified` routing to operator mapping | **Yes.** It changes what intake does with a given emission, and the emission is recorded |
| **Row 22**, seven declared classes | **Yes.** It changes which classes intake and the control grid admit |
| **The sign refusal** | **Yes.** It is a registration check over a directive |
| **B5**, the class table supplied and enforced | ***NO.*** It changes what the model is **asked**, so only a live call can show it. A transcript replays a reply given under the old prompt and cannot produce the reply the new one would draw |
| **A4**, `strict` | ***NO.*** Same reason: it constrains the transport of a live call |

**So B5 and A4 are tested by the suite and are not evidenced here**, and this
file says so rather than letting a green diff imply otherwise.

### A reproduces the run of record

**Column A matches `docs/runs/2026-08-27_funnel_12.md` §3 line for line**: six
`scoring_mode_unsatisfiable`, three `duplicate_of_open_pointer`, three each of
the registration blockers, three directives built. *That is what makes the
fixture usable: it is checked against the report before it is used to show
anything.* The one difference is `agent_payload_not_a_list`, which the run of
record recorded once and which a transcript of already-parsed proposals cannot
reproduce.

### What B shows: the ceiling comes down

**Six refusals move from `scoring_mode_unsatisfiable` to
`stream_unmapped_pending_operator`.** The agent arm's proposals stop dying at
intake point 9 and reach `screen.build_directive`, which handles the class
correctly and hands it to the operator to map a stream.

***The code that fires had never been emitted once in this project's history.***
It sat in the run report's own defined-but-never-emitted list of thirty-seven,
which is §9.4's failure class — *a rule that is wrong because nothing ever
reached it* — inside the layer §9.4 is aimed at.

**The six proposals are not thereby admitted.** They are refused, with a code
that names what is actually missing (a stream) instead of one that named
something else (an exclusivity construction). §13 row 19's arms are still
uncomputable on this sample, because *n*ₘᵢₙ is 30 per arm and this is six; what
changes is that the asymmetry deciding them is gone.

### What C adds: two more dead branches exercised

Declaring all seven classes puts `index_reconstitution` and
`short_interest_disclosure` into the control grid, and their stream statuses are
`new_subscription` and `manual_observation`. Both refuse, **each with its own
correct code**, and both codes were previously never emitted. The two declined
feeds are logged with the feed each named, which is P56's declined-directive log
receiving its first entries.

**Reason-code coverage over this fixture moves from 6 emitted to 9**, and the
registry gained one (`registered_sign_absent`), so 44 defined becomes 45.

### The sign refusal fires, and it should

`registered_sign_absent` appears three times in B and twice in C: once per
directive built. Every directive this layer produces is blocked on it, which is
correct — **the sign is one of the four things §3.6.8 says nothing machine-raised
may supply**, and it was the only one of the four that nothing refused on.

## What has not changed, stated because a replay invites the opposite reading

- **Zero directives registered. Zero promoted. Zero capital. Zero backtests.**
- **The queue is still blocked on the operator**, on four inputs and now
  explicitly on the sign as well. That is the designed steady state and the
  repairs do not shorten it.
- **Nothing here is a fact about a market**, about the corpus, or about whether
  any mechanism works.

## How to reproduce

**Columns B and C**, from the repo root of this branch:

```
python docs/replay/drive.py
```

**Column A** needs the pre-repair code, so it runs against an extracted tree
rather than a checkout, which leaves this working tree untouched:

```
rm -rf /tmp/old && mkdir -p /tmp/old
git archive db1c463 | tar -x -C /tmp/old
cp docs/replay/run_of_record_agent_emissions.json /tmp/old/
cp docs/replay/drive_pre_repair.py /tmp/old/drive.py
cd /tmp/old && PYTHONPATH=src python drive.py
```

*The extracted tree carries `db1c463`'s registration as well as its code, which
is what makes column A the run of record's own configuration and not this
branch's under old code.*

Both drivers take the registration from the tree they run in and the payloads
from the fixture, and both write to a temporary ledger which they delete. **They
write nothing to `docs/runs/`**, because a replay is not a run and a run report
is the record of a sweep.
