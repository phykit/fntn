  that subject.

THE ENTITY FENCE MEASURED AGAINST corpora/us
  The corpus supports one reading without an agent: run entity_mentions over
  the document text and count what the fence would refuse.

                              before        after
    distinct hits                 41           10
    total hits                   257           68

  Before, essentially every hit was false and every one came from the ticker
  half of the lookup: Law, Are, For, Help, Note, Any, Such, When, and the
  single letters B, C, D, E, F, H, J. 7,268 of the 10,388 US tickers are four
  characters or fewer, and the loader applied its minimum-length and lexicon
  filters to issuer names only, so the ticker set entered the fence unfiltered
  and sentence-initial capitalisation was enough to trip it.

  After, the ticker branch matches only all capitals of three characters or
  more, and names and tickers are separate lookup sets. The residue is five
  tokens: LII, CFR, ACT, III and VII, which are legal and site vocabulary
  colliding with tickers and are candidates for a lexicon row. BlackBerry and
  Opera are genuine issuer names appearing in the Cornell LII page furniture,
  which is the corpus fetch including site chrome rather than a fence defect.

  The rule takes on a false negative and names it: a bare ticker in lower or
  title case is now invisible. That cost was taken over the alternative, a
  common-word filter on the ticker set, which would have made at least 95 real
  US issuers invisible in all capitals as well and would still have left CFR,
  LII, III and VII needing a lexicon row.

THE CHROME STRIP, AND WHAT IT DID NOT FIX
  API, BlackBerry and Opera were diagnosed on 27 August as a corpus-fetch defect
  belonging to §13 row 22 rather than a fence defect: issuer names sitting in
  Cornell LII's page furniture, on thirteen documents that name no company at
  all. scripts_fetch_us_corpus.sh now strips that furniture before the file is
  written, removing <nav>, <header> and <footer> and any element whose class or
  id contains nav, menu, sidebar, related, footer or breadcrumb, and the
  manifest records raw_bytes beside bytes so what was discarded is on the
  record. The strip removed 154,132 of 638,883 bytes, 24% of the corpus, across
  all thirteen documents; the integrity check passes with the floor applied to
  the stripped size, smallest document 17,387 bytes against a 4,000 floor.

  It did not remove any of the three. Re-measured on the stripped corpus, the
  fence still refuses API 13 times, BlackBerry 13 times and Opera 13 times, once
  per document, and the residue is the same five tokens at the same 41 hits.

  The reason is that none of the three is in the furniture the rule names.
    API         an HTML comment in <head>: <!-- API url -->, labelling the
                script that sets LII's search endpoint.
    BlackBerry  string literals inside an inline <script> in <head>, in a
    Opera       user-agent sniffer: /BlackBerry/i, /Opera Mini/i.
  <head> is not <header>, a comment carries no class or id, and a <script> block
  carries none either. The strip is doing what it was specified to do; the
  specification did not reach these three.

  What would reach them is removing <script>, <style> and HTML comments as well.
  That is a wider rule than the one asked for and it changes what the agent is
  shown, so it is left as an operator decision on row 22 rather than taken here.
  Recorded so the next reader does not re-diagnose it: this is one line in
  CHROME_TAGS plus a handle_comment that drops rather than emits.

  The rule takes on a false negative and names it: a bare ticker in lower or
  title case is now invisible. That cost was taken over the alternative, a
  common-word filter on the ticker set, which would have made at least 95 real
  US issuers invisible in all capitals as well and would still have left CFR,
  LII, III and VII needing a lexicon row.
